# Журнал упрощений (tech-debt)

Осознанные упрощения ради скорости. Каждое — с рецептом «как поправить».
Помечай `[ ]` → `[x]` когда закрыто.

## Открыто

### [ ] 1. Данные читаются из локальных фикстур, а не из Supabase
- **Где:** `src/_shared/supabase/isConfigured.ts` + репозитории (`repository/*`), фикстуры в `src/_shared/mock/`.
- **Почему:** нет Supabase-ключей на этапе разработки — чтобы приложение было полностью кликабельным уже сейчас.
- **Как поправить:** когда появятся `.env` ключи, `isSupabaseConfigured` станет `true` автоматически и репозитории пойдут в реальный `sb.from(...)`. Проверить маппинг DTO под фактическую схему, удалить `mock/` когда не нужен.

### [ ] 2. Записи (create/update/upload) пока «оптимистично-локальные»
- **Где:** мутации в сторах фичей + `api/*` методы `_fn(...)`.
- **Почему:** Edge Functions ещё не задеплоены (нужен Supabase проект + токен бота).
- **Как поправить:** задеплоить функции из `supabase/functions/`, включить реальные вызовы. Код функций уже написан — только деплой + секреты.

### [x] 3. Загрузка обложек рецептов
- Закрыто: Edge Function `cover-upload` (проверка админа + service_role) заливает в

  Нужен деплой функции `cover-upload` (см. README, шаг 5).

### [x] 4. Sass legacy-js-api deprecation warning при build
- Закрыто: включён `css.preprocessorOptions.scss.api = 'modern-compiler'` в `vite.config.ts`.

### [ ] 5. Единый inline edit-режим упрощён до отдельного экрана-редактора
- **Где:** `pages/RecipeEditor.vue`, `features/admin/model/edit-mode.store.ts` (`isEditing` пока не используется).
- **Почему:** быстрее и надёжнее, чем inline-редактирование каждого поля прямо на экранах.
- **Как поправить:** если захочется «карандаш → поля редактируемы на месте» — задействовать `isEditing` и рендерить инпуты по месту в `RecipePage`/`HomePage`/`CategoryPage`. Сейчас: админ видит «+» (категория) и карандаш (рецепт), которые открывают `RecipeEditor`.

### [ ] 6. Редактор рецепта — локальный reactive-стейт + zod safeParse (не vee-validate)
- **Где:** `pages/RecipeEditor.vue`, `features/recipes/forms/recipe.form.ts`.
- **Почему:** динамическая форма с 5 уровнями вложенности (секции→ингредиенты/замены/шаги/хранение). Field-array vee-validate тут громоздкий и на этапе без бэкенда непроверяемый.
- **Как поправить:** при росте требований к валидации — перевести на `useMyForm` + `FieldArray`. Ядро форм (`useMyForm`, `SmartField`, `form.helper`) уже портировано и готово.

### [ ] 7. Управление категориями не сделано (категории фиксированы/сидируются)
- **Почему:** набор категорий стабилен (Суп…Торт), CRUD категорий — избыточен для MVP.
- **Как поправить:** при необходимости добавить экран/модалку управления категориями + edge function. Сейчас категории задаются сидом в БД (`supabase/migrations`) и фикстурами.

### [ ] 8. Dev-переключатель админа (?admin=1) — временный
- **Где:** `features/admin/model/edit-mode.store.ts`.
- **Почему:** чтобы превьюить edit-режим без Telegram, пока нет `verify-admin`.
- **Как поправить:** на этапе 6 заменить на реальную проверку (Telegram initData → `admins`). Убрать чтение `localStorage['dev.admin']`.
